# Executive Storytelling

## When to use
For any deliverable read by C-level / board / steering committee — a deck, a memo, a verbal readout.

## Pyramid Principle (Barbara Minto)

Start with the answer, then support it. Top-down, not chronological.

```
Recommendation (the SO WHAT)
    ↓
Supporting argument 1 + 2 + 3 (MECE)
    ↓
Evidence / data per argument
```

Executive consumes the top of the pyramid. The bottom is for those who want to drill in.

## SCQA framing (Situation / Complication / Question / Answer)

Use to set up any executive memo or deck:
- **Situation:** What the audience already accepts as true
- **Complication:** What disrupts the situation; why we're here now
- **Question:** The specific decision needed
- **Answer:** The recommendation

Example:
- *S:* We've grown to $X revenue with the current ops model.
- *C:* But fulfillment cost per order is rising 12% YoY while industry benchmark is flat.
- *Q:* How do we re-engineer fulfillment to bring cost in line?
- *A:* Consolidate to 2 regional DCs and outsource last-mile in low-density geographies.

## SCR (Situation / Complication / Resolution) — for verbal updates

Same structure, compressed. Useful for status updates, not full recommendations.

## The 30-second test

Imagine the executive reads ONLY the first 30 seconds of your deliverable. Do they have the answer?
- ❌ "We analyzed three options and considered the trade-offs…"
- ✅ "Recommend Option B (regional DCs + outsourced last-mile). Saves $12M / yr. Risk: 12-month transition. Three slides explain why."

## Board-deck patterns

| Slide type | Content |
|---|---|
| Title | Topic + decision needed + date + author |
| Executive summary | Recommendation + 3 supporting bullets + ask |
| Context | What changed since last update / why now |
| Options | 2-4 options with criteria comparison |
| Recommendation | The pick + rationale |
| Risks | Top 3 risks + mitigations |
| Financials | Cost / benefit / payback / cumulative cash |
| Implementation | Phased plan with key dates |
| Asks | What you need from the board (decision, resources, sponsorship) |
| Backup | Detailed analysis (not walked through, but available) |

## Words to delete

- "I think" (you're paid to think — say it)
- "Should be" (will be? could be? clarify)
- "Synergies" (specific revenue or cost?)
- "Best practice" (whose?)
- "Going forward" (when?)
- "Leverage" / "operationalize" (hide weak verbs)

## Sentence patterns

| Vague | Specific |
|---|---|
| "Improve customer satisfaction" | "Lift NPS from 22 to 35 by Q4 2027" |
| "Reduce cost" | "Take $8.5M out of fulfillment by FY28" |
| "Deploy AI" | "Replace 40% of L1 service tickets with the AI assistant by Q2" |

## Verbal storytelling

For 5-minute readouts:
- 30s: state the recommendation + why now
- 90s: the 2-3 supporting arguments
- 90s: the data / evidence
- 60s: risks + mitigations
- 30s: ask

## Quality bar

- The first sentence/slide states the recommendation
- The recommendation is testable (specific, measurable)
- Supporting arguments are MECE and pyramid-structured
- Evidence is sourced; numbers are precise
- The "ask" is explicit
- Length is appropriate for audience (board ≤15 slides; team ≤30)

## Common failure modes

- Chronological narrative ("first we did X, then Y, then Z")
- Recommendation buried at the end
- "Synergies" / "transformation" without dollar amounts
- Slides full of bullet text (eye chart)
- No explicit ask (audience leaves wondering what's expected)
